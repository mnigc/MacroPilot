# MacroPilot — 代币化股票的链上智能投顾

> BNB Hack: 代币化股票专题（16 Sep – 11 Oct 2026）参赛项目
>
> **在线演示：https://macro-bnb.soulcreator.cn** ｜ 数据新鲜度自查：https://macro-bnb.soulcreator.cn/last-run.txt
>
> 用一句话说清楚：**一个永不停歇的链上 robo-advisor——定投买入你的股票篮子，财报前自动避险，宏观转冷自动降仓，周末照常工作。**

## 产品定义：四个策略引擎，一个执行器

真实 robo-advisor 的架构：每个引擎在不同时间尺度上输出**目标权重**，合成一张目标表后由唯一的执行器完成"现状 → 目标"的链上调仓。

| 引擎 | 时间尺度 | 职责 | 官方灵感对应 |
|---|---|---|---|
| 定投引擎 | 每周五 | 新资金按目标权重买入篮子 | 自动定投 |
| 体制引擎（内核） | 每日 | 宏观信号 → 总股票仓位 100%/60%/25%（三态滞回） | 组合智能体 / 混合组合 |
| 漂移引擎 | 每日 | 个股权重偏离 >5pp 拉回 | 阈值再平衡 |
| 财报引擎 | 事件驱动 | 财报前 48h 该股减半，财报后恢复 | 财报日历智能体 |

另有一个**只读监控模块**（不产生交易）：链上可成交溢价——同一股股票，链上买到手比美股官方价贵多少。
它是官方灵感清单上的"链上与参考价监控"，实现细节与一处重要的口径纠常见 [DX-LOG D3](./DX-LOG.md)
与站点 `/spread` 页（数据端点给的"链上价"其实是发行方净值标记，减参考价恒为 0，必须用聚合器询价才拿得到差价）。

资金两筒：**股票筒**（代币化股票篮子）+ **稳定币筒**（USDT）——体制引擎降风险 = 股票筒流向稳定币筒，这就是「TradFi-加密混合组合」的落地形态；risk-off 时稳定币筒进 DeFi 收益（stretch goal）。

**为什么传统券商做不到**：定投和再平衡被交易所营业时间锁死，财报避险要人盯日历。链上组合 7×24 在场——这套策略只有在代币化股票上才是全自动的。

## 当前状态与已知边界

诚实口径，按"已验证 / 已实现待验证 / 未实现"三档标注：

| 能力 | 状态 |
|---|---|
| 体制引擎（FRED 四信号 + 三态滞回）、回测框架、paper 执行器 | 已用真实数据端到端验证 |
| RWA 数据端点、聚合器询价/构造交易 | 已对真实 API 验证（字段、参数名、单位全部按实测收紧，见 DX-LOG D3） |
| 链上可成交溢价监控（询价→入库→看板） | 已实现并有真实快照：`npm run spread` + `/spread` 页 |
| 同一 ticker 多枚链上代币的可成交性选币 | 已实现，离线测试用 MSFT 真实两枚地址锁住行为（`tests/tokens.test.ts`） |
| EIP-712 本地签名、载荷归一化、报价选单 | 已实现并有离线验签测试（不依赖网络与资金） |
| 执行链路真实广播（SWAP 上链 / RFQ 撮合往返） | 代码已接好，**尚未真实下过单**：需要一只充值后的小额专用钱包（当前 `.env` 的 `WALLET_PRIVATE_KEY` 为空，`npm run wallet` 会列出准备清单） |
| 站点部署 + CI 每日驱动（决策 → 写库 → 触发重建） | 已上线并端到端验证：2026-09-26 CI 产出 backtest run 14，push 后线上 `/last-run.txt` 与 `/api/backtest.json` 同步刷新 |
| 财报引擎 | 在执行器生效；因免费源无法回溯 6.5 年历史财报日，**不参与回测** |

一处重要的口径纠正：币安 RWA 数据端点的 `tokenPrice` 实测恒等于 `referencePrice × tokenToShareRatio`
（发行方净值标记，无盘口），据此算出的"链上-参考价差"必然为 0。本项目因此把溢价改挂在
**聚合器可成交单价**上——实测 Mag7 每笔 50 USDT 的溢价在 −0.00% ~ +1.34% 之间浮动，且随询价路由漂移。

第二处：同一个 ticker 在 BSC 上往往有 ondo / bstock 两枚代币，而列表里的 `volume24H` 是**底层美股**的成交额，
跟链上有没有盘口无关。按它选币会选中无法成交的那一枚（实测 MSFTon 50 USDT 只换到 4.8e-8 股、冲击 99.95%，
同标的 MSFTB 冲击 0.00%）。所以下单与采集前都对全部候选逐枚询价，剔除冲击成本超阈值者后再选（`resolveTokens({probe})`）。

一条还没跨过去的边界：以 50 USDT 名义额实测 AMZN 的冲击就有 1.77%，已经高于配置里单笔冲击上限 1%——
live 模式下 AMZN 会被护栏直接拒单。要么加大单笔金额换来更好的路由，要么放宽阈值并承受成本，这是真实资金下的第一个待决参数。

样本口径：2020→今几乎全程单边牛市，择时的必然代价是绝对收益少赚。因此本项目的成绩按
**风险调整口径**读——最大回撤 −31.4% vs 买入持有 −53.7%，夏普 1.59 vs 1.28；两腿的现金流
（初始 $10,000 + 每周定投）与费率待遇完全一致，对照是公平的。

## 快速开始

```bash
npm install
cp .env.example .env      # 填入 BINANCE_API_KEY / BINANCE_SECRET_KEY + DATABASE_URL（dev-portal 申请）
npm run smoke             # 连通性验证（全程只读）：平台/份额比/篮子逐候选选币 + 可成交溢价对照表
npm run spread            # 采集一轮溢价快照写入 Postgres（/spread 页的数据源）
npm run wallet            # 只读资金体检：地址一致性、BNB gas、USDT 与篮子持仓余额（live 前置检查）
npm test                  # 签名、体制状态机、回测不变量、EIP-712 验签单元测试
npm run backtest          # 宏观信号 + 回测 → 结果持久化 Postgres
npm run agent             # 执行器单次运行：四引擎 → 目标权重 → paper 成交（周五自动定投）
cd web && npm install && npm run build   # 可视化平台（构建时直读 Postgres）
```

回测产物 `data/backtest/result.json` 不入 git（由 `npm run backtest` 现生成）；股价与财报日历
CSV 随仓库分发，clone 即得。

## 可视化平台（web/）

Astro + React + ECharts，与 invest-platform 同栈。**线上：https://macro-bnb.soulcreator.cn**
（Cloudflare Workers Builds 托管静态产物：根目录 `web`、构建 `npm run build`、部署 `npx wrangler deploy`，
配置见 `web/wrangler.jsonc`）。静态构建时直读 Supabase Postgres：

- **仪表盘 `/`**：paper 组合净值、当前体制徽章与综合分、四信号分量、四引擎状态卡、持仓权重、最近交易
- **回测 `/backtest`**：策略 vs 买入持有指标对比、净值曲线（体制色带 + 缩放）、宏观综合分与切换阈值、体制时间占比、参数表
- **交易记录 `/trades`**：paper 执行记录 + 回测成交抽样（逐笔标注**全部**触发引擎，同一天可多值）
- **链上溢价 `/spread`**：每股可成交溢价（红＝比美股贵、绿＝折价）、冲击成本、实际询价路由，附"为什么不能用数据端点的链上价减参考价"的口径说明
- **程序化接口**：`/api/backtest.json`、`/api/regime.json`（静态产出）

数据管道由 CI 驱动，不依赖有人手动敲命令——这是"永不停歇"成立的前提：

- `sync-data.yml` 每交易日 UTC 00:30 同步股价与财报日，提交 CSV
- `run-agent.yml` 每交易日 UTC 01:30 跑执行器（paper）与回测写库，再提交一个时间戳触发站点重建
- 溢价快照**不能进托管 CI**：币安 Web3 API 对 GitHub runner 出口 IP 返回 `40304` 合规拦截
  （本机同一份 key 正常），故由本机计划任务跑 `scripts/capture-premium.ps1`

两处外部网络约束（配置时踩到的，尚未整理进 DX-LOG）：Supabase 直连主机
`db.<ref>.supabase.co` 只有 AAAA 记录，runner 无 IPv6 路由，CI 须改用 Session pooler 串；
构建产物是静态的，所以写库之后必须有一次 push 才会刷新页面。
