# MacroPilot — 宏观体制驱动的全球股票投资平台

> 在线演示：https://macro-bnb.soulcreator.cn ｜ 数据新鲜度自查：https://macro-bnb.soulcreator.cn/last-run.txt
>
> 用一句话说清楚：**一个把宏观信号翻译成股票仓位的个人投顾——定投买入股票篮子，财报前自动避险，宏观转冷自动降仓，贵了自动收敛；每个引擎的贡献用消融实验证明，每个结论用置信区间与 walk-forward 检验，全部纸面成交、可回测、可复现。**

## 产品定义：六个策略模块，一个纸面执行器

每个模块在不同时间尺度上输出**目标权重**，合成一张目标表后由唯一的执行器完成"现状 → 目标"的调仓。

| 模块 | 时间尺度 | 职责 |
|---|---|---|
| 定投引擎 | 每周五 | 新资金按目标权重买入篮子 |
| 体制引擎（内核） | 每日 | 五路宏观信号 → 总股票仓位 100%/75%/25%（三态滞回）；Sahm 衰退确认门触发时仓位上限压回防御档 |
| 波动率目标 | 每日 | 21 日已实现波动高于目标（18%）按比例减仓，不杠杆——体制档位上的连续乘数 |
| 估值锚 | 每月 | CAPE 滚动百分位 → ±10% 线性偏移：贵时少买，便宜时多买 |
| 漂移引擎 | 每日 | 个股权重偏离 >5pp 拉回 |
| 财报引擎 | 事件驱动 | 财报前 2 天该股减半，财报后恢复；历史财报日已回填，**参与回测** |

合成口径：`目标股票仓位 = 体制档位 × 波动率乘数 × (1 + 估值偏移)`，个股层再叠加财报缩放。
两个叠加层是乘数不是投票——所以消融实验能把每一层的边际贡献干净地拆出来
（2026-09-29 实测，run #24：纯定投夏普 1.37 → +体制 1.69 → +波动率目标 1.96 → +估值锚 2.04，
最大回撤从 −45% 压到 −19.3%）。

资金两筒：**股票筒**（等权篮子）+ **现金筒**——降风险 = 股票筒流向现金筒，现金按 DGS3MO 日频计息。

回测主口径（2026-09-29，run #24，2020-01→2026-09，成本暂按 50bps 平坦退回假设）：
全引擎 CAGR +32.6%，最大回撤 **−19.3%** vs 买入持有 −52.9% / 60/40 −31.4%；
夏普 **2.03** vs 1.31 / 1.22；夏普 95% 置信区间 [1.25, 2.85]（块自助法）。
walk-forward 四个 OOS 年份里，IS 选参的样本外表现与现行参数同量级——结论不依赖精调的参数值。

## 快速开始

```bash
npm install
cp .env.example .env      # 填入 DATABASE_URL（Supabase Postgres 连接串）
npm test                  # 39 个单测：状态机/Sahm 门/叠加层/成本/计息/自助法/类比窗口
npm run backtest          # 消融跑批 + 统计产物 → Postgres（5 条 run + run_artifacts）
npm run sweep             # 参数敏感性网格 + walk-forward → 挂最新 run
npm run agent             # 执行器单轮：六模块 → 目标权重 → 纸面成交（写下一轮预告）
npm run agent:dry         # 全流程只算不写（预告同源，用于核对）
python scripts/sync-prices.py        # 股价(OHLCV) + 财报日历（本地被 Yahoo 限流时由 CI 跑）
python scripts/sync-valuation.py     # Shiller CAPE 月度 → data/valuation/cape.csv
npm run import-csv                   # CSV → DB（价格含成交量、财报日）
cd web && npm install && npm run build   # 可视化平台（构建时直读 Postgres）
```

真实成交导入：把券商成交记录整理为 `date,ticker,units_delta,price`（units 带符号）CSV，
`npm run import-real -- <路径>` 整分区重建 `mode='real'` 账本；trades 页会给出每笔的
实测滑点（真实成交价 vs 同日收盘），用于校准回测成本模型。
事件推送：配置 `ALERT_WEBHOOK_URL`（通用 JSON）或 `DISCORD_WEBHOOK_URL`（Discord 格式），
执行器在财报避险生效或发生成交的轮次推送。

回测产物 `data/backtest/result.json` 与 `data/valuation/cape.csv` 的提交策略见
`.github/workflows/sync-data.yml`；股价/财报/CAPE CSV 随仓库分发，clone 即得。

## 可视化平台（web/）

Astro + React + ECharts。**线上：https://macro-bnb.soulcreator.cn**
（Cloudflare Workers Builds 托管静态产物：根目录 `web`、构建 `npm run build`、部署 `npx wrangler deploy`，
配置见 `web/wrangler.jsonc`）。静态构建时直读 Supabase Postgres：

- **仪表盘 `/`**：paper 组合净值、体制徽章（含 Sahm 门提示）、五信号分量、目标仓位三层合成、
  **下一轮预告**（下轮定投分配 + 漂移读数 + 未来财报）、**历史类比**（宏观形态最像现在的历史窗口及其后走势）、六模块状态卡
- **回测 `/backtest`**：三腿对照（策略/买入持有/60/40）、**引擎消融表**、净值曲线（体制色带）、
  **月度收益热力图**、**滚动 12 个月夏普**、**蒙特卡洛前景扇形**（含 12 个月回撤概率）、
  **块自助法置信区间**、**参数敏感性热力**、**walk-forward 对照**、参数表、方法论声明
- **交易记录 `/trades`**：执行心跳、该轮成交、下一轮定投倒计时、paper 流水（逐笔标注全部触发引擎 + 逐笔成本）、
  **真实账本实测滑点对照**
- **标的走势 `/ticker/[ticker]`**：K 线 + 体制色带 + 全部买卖点（分页浏览）
- **程序化接口**：`/api/backtest.json`、`/api/regime.json`（静态产出）

数据管道由 CI 驱动，不依赖有人手动敲命令："永不停歇"成立的前提：

- `sync-data.yml` 每交易日 UTC 00:30 同步股价/成交量/财报/CAPE → 入库 → 提交 CSV
- `run-agent.yml` 每交易日 UTC 01:30 跑执行器（paper）与回测写库，再提交时间戳触发站点重建

构建产物是静态的，所以写库之后必须有一次 push 才会刷新页面。

## 方法论声明

- 回测回答的是"同一规则在同一历史上的相对表现"——三腿对照、消融、参数邻域稳定性都是内比较，不依赖预测。
- 类比窗口与蒙特卡洛是条件化的历史统计，前提是"未来长得像过去"；页面上没有任何一项输出是预测。
- 成本模型是估计：实测滑点请用真实账本对照功能校准。
- 样本只有一轮 2020→今的牛熊；结论的可信度以自助法区间与 walk-forward 为界，不以曲线美观为界。
